## Product purpose
The personal portfolio of Alex Platret. The site is not a description of the work; it is itself the work. A visitor should leave certain that Alex is a strong coder because the page in front of them is proof, not because a sentence claimed it.

One line a competitor would use: "a developer portfolio." If the build ever reads like that generic sentence, it has failed.

## Users
Three audiences, one surface, no compromise between them:

1. **Friends and peers** want a share-worthy "whoa, look at this" moment. Served by the one playable hero (BOOT ENGINE) and the overall craft.
2. **The dev community** wants the hard-to-fake engineering signals juniors usually botch: a real fixed-timestep loop, allocation-free rAF, honest performance numbers, status wired to real deploy state, a reduced-motion path that actually works. They respect rigor, not decoration.
3. **Recruiters** (frontend-leaning) want the facts in five seconds and proof a 17-year-old's claims are real. Served by a scannable spec sheet, count-up real metrics, and a resume/skim path that is always one tap away so they are never trapped by the interactive parts.

Primary desired action: remember the name and reach out (email or GitHub). Secondary: open a live project.

## Brand voice
Three physical-object words: **precise, mechanical, honest.** The reference object is a builder's control console read in a dim room: warm graphite metal, amber phosphor readouts, hairline seams, every number meaning something. Against that cold instrument runs exactly one warm human line in Alex's own voice, so the site reads as a person, not a dashboard template.

Copy rules: every word earns its place. No restated headings. No em dashes anywhere. Plain, exact, a little dry. Never "passionate about clean code."

## Chosen creative direction
The Remix (selected Phase 1): a warm-graphite instrument shell ("Flight Deck") as the always-honest skeleton, with one genuinely playable ChipStack BOOT ENGINE moment as the wow, and each project's detail rendered as a leader-lined SVG technical schematic ("Drawing No. AP-2026"). One shell, three audiences.

## Strategic principles
1. **The site is the proof.** Demonstrate, never assert. Live solver, real rAF frame readout, status LEDs wired to actual deploy state.
2. **Honesty is the moat.** No fake live demos. KillerSudoku and Smartii-for-Mac read REPO-ONLY (amber), never a green LIVE dot. Every metric is real or it is cut.
3. **Five-second legibility.** A recruiter gets the facts (who, the ICT result, the stack, the live projects) without interacting. The skim/resume path is always one tap away.
4. **One wow, not five.** A single deep playable moment. Everything else is scannable instrumentation.
5. **Accessibility and reduced-motion are built first** and surfaced as visible craft, not hidden plumbing.

## Anti-references (do not become these)
- The generic AI dev portfolio: dark background plus purple-to-blue gradient, glassmorphism cards, "Hi, I'm Alex" wave hero, floating particle or blob fields, bento grid of everything, typewriter effect, marquee strip of tech logos, the big-number-plus-gradient hero-metric template.
- Alex's current GitHub profile README (purple #7C3AED capsule gradient, shields.io badge walls, animated emoji). The portfolio must read as the deliberate opposite of that.
- The editorial-magazine lane (display-serif plus italic plus drop caps plus broadsheet grid). This brief is an instrument, not a magazine.

## The slop test for this project
A visitor should ask "how was this made?", never "which AI made this?" If the theme and palette are guessable from "developer portfolio" (dark plus an accent), rework until they are not. The instrument-panel concept, the honest live data, and the warm-graphite-plus-phosphor palette are what carry it past the reflex.
